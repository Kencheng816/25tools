# 上傳步驟（GitHub／GitLab 通用）

2026-10-14 起**不使用 Git LFS**（與 18節 整合版同一做法）：整個專案約 490MB、單檔最大 72MB，一般 git 放得下
（GitHub 單檔上限 100MB、整個 repo 建議 1GB 內；GitLab 依設定通常 10GB）。
不用 LFS 的理由：GitHub 的「Download ZIP」與 GitHub Pages 不含 LFS 真檔、沒裝 git-lfs 的電腦 clone 只拿到指標檔、
免費方案 LFS 流量 1GB/月幾次就用完——字型／素材一旦變成 130 byte 的指標檔，程式會悄悄用替代字型，產出的圖就錯了。

## 第一次上傳（全新／重建 repo）
前置：GitHub／GitLab 建好**空**專案，本機裝好 `git`。**不需要** git-lfs。
上傳前先跑一次 `npm run check`（會檢查沒有 LFS 指標檔、`.nojekyll` 在、公版 bundle 同步）。

```bash
cd "D:\#AI測試\#25節專案\#整合版本\25節Tool_整合版"
Remove-Item -Recurse -Force .git   # 重建 repo 才需要：砍掉帶著「字型在 LFS」的舊歷史（PowerShell；bash 用 rm -rf .git）
git init -b main
git add .
git status --short | Select-String -Pattern "node_modules|golden-diff|work/"   # 必須是空的（.gitignore 已排除）
npm run check                      # 會順便檢查沒有 LFS 指標檔、.nojekyll 還在
git commit -m "25節Tool 整合版：一校一修（公版內建、匯入彈窗、調整面板、商品合成、工單編號檔名；12 案例黃金全綠）"
git remote add origin <repo 的 .git 網址>
git push -u origin main            # 約 490MB；GitHub 對 72MB 的那張 PNG 會給 warning，可以忽略
```

## 已經用 LFS 推過的 repo → 換回一般檔（做一次；重建 repo 的話不用）
```bash
cd "D:\#AI測試\#25節專案\#整合版本\25節Tool_整合版"
git pull                                       # 先確定本機是最新
git lfs install                                # 這一步還需要 git-lfs（只為了把物件取回）
git lfs fetch --all && git lfs checkout        # 確定本機都是真檔
git lfs migrate export --include="*" --everything   # 把歷史裡的 LFS 物件全部換回一般檔（會改寫歷史）
git add .gitattributes && git commit -m "停用 Git LFS，改一般 git 存放" || true
git push --force --all origin
git lfs uninstall                              # 之後 clone 的人不需要 git-lfs
```
推完後到 GitHub／GitLab 的 Settings 把 LFS 物件刪掉可釋放額度（GitHub：Settings → Archives／Git LFS objects）。

## GitHub Pages（用網址直接開工具）
1. GitHub repo → Settings → Pages → Build and deployment：Source 選 **Deploy from a branch**，Branch 選 `main`、資料夾 `/ (root)` → Save。
2. 根目錄的空檔 **`.nojekyll` 一定要在**（已內建）：Pages 預設用 Jekyll 處理網站，Jekyll 會略過所有底線開頭的檔案，
   `config/profiles/_defaults.js` 就會 404，畫面出現「分類「XX」啟用失敗：載入失敗：config/profiles/_defaults.js」。`npm run check` 會檢查它還在。
   已經推上去才發現：確認本機根目錄有 `.nojekyll`（`ls -a`），`git add .nojekyll && git commit -m "add .nojekyll" && git push`。
3. push 後約 1 分鐘重新部署；瀏覽器用 Ctrl+F5 強制重新整理。網址 `https://<帳號>.github.io/<repo>/`。

## 怎麼確認修好了
- 用「Download ZIP」或在沒裝 git-lfs 的電腦 clone 一份，`node tests/check-lfs-pointers.js` 要印出「沒有 Git LFS 指標檔」。
- 雙擊 `index.html` 開工具：沒有跳出紅色「字型沒有載入」視窗就是正常（有跳出代表 `fonts/` 下仍是指標檔）。

## 注意
- 資料夾名含 `#`，PowerShell 請整段加引號。
- AMS 有輸出檔名含 `*`（原工具現況），只在 zip 內，不會進 repo。
- 之後每次更新：`git add -A && git commit -m "..." && git push`。
- CI：GitHub 讀 `.github/workflows/ci.yml`（push 自動跑 `check`；main 分支或手動 Run workflow 才跑 `golden`，約 30～60 分鐘，跑 ubuntu-22.04＋同一組字型，不然像素會差），GitLab 讀 `.gitlab-ci.yml`。Actions 頁紅叉先看是哪一步：`check` 失敗通常是公版 JSON 改了沒跑 `npm run bundle:templates`；`golden` 失敗會留下 `golden-diff` artifact（差異圖）。
- 線上版字型：工具頁先抓 `https://raw.githubusercontent.com/jimmywu-commits/shopee/main/fonts/*.woff2`（`config/fonts.js`），公司網路擋了就自動退回 repo 內建的 `fonts/*.ttf`（第一次開頁會慢一點）；兩個都讀不到才會跳紅色視窗。
- 線上版有 Service Worker（`sw.js`）：更新後使用者第一次開頁仍可能看到舊版，底部會跳「工具有新版本，重新整理即可使用」；要強制清掉可在網址加 `?sw=0`。
